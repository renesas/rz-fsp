Detailed Description

Driver for the Trusted Secure IP on RZ microprocessors. This module implements the TSIP Interface.

Overview

This library is a highly secure cryptographic driver using Trusted Secure IP, a peripheral function of RZ microprocessors, and is called TSIP driver.

The keys handled by the TSIP driver (keys to be input and keys to be output) are opaque keys wrapped in device-specific keys that can only be accessed by the Trusted Secure IP. Secure key management in the TSIP driver is achieved by wrapping the keys with device-specific keys, which enables key secrecy and tamper detection capabilities outside of the Trusted Secure IP. Only the Trusted Secure IP can unwrap the key, and the unwrapped key exists only inside the Trusted Secure IP during cryptographic operations. Because the key is wrapped with a device-specific key, even if the key is copied to another device, the key cannot be unwrapped by another device with a different device-specific key. Because keys can be securely managed in this way, a secure storage function can be built into user applications by encrypting data to be kept secret using symmetric cryptography such as AES and storing it in flash.

Unauthorized access monitoring by Trusted Secure IP covers all cryptographic operations provided by this driver and is always enabled during cryptographic operation. If the cryptographic operation tampering is detected during using this driver, this driver stops operation.

Features

This driver provides interfaces for the following features. To check which of these are supported by each RZ/V series product, refer to the section Supported Algorithms.

  • Key Management
    • Key update
    • Key generation and key pair generation
    • Public key export
  • Random Number Generation
  • Symmetric Cryptography
    • AES
      • Encryption
        • ECB/CBC/CTR
      • Authenticated Encryption with Associated Data (AEAD)
        • GCM
      • Message Authentication Code (MAC)
        • CMAC
    • ChaCha
      • ChaCha20
      • ChaCha20-Poly1305
  • Asymmetric Cryptography
    • ECC
      • Signature
        • ECDSA
    • RSA
      • Cryptographic primitive
      • Encryption scheme
        • RSAES-OAEP
        • RSAES-PKCS1-v1_5
      • Signature scheme
        • RSASSA-PSS
        • RSASSA-PKCS1-v1_5
  • Hash Functions
    • Message digest
      • SHA1, SHA2
    • Message Authentication Code (MAC)
      • HMAC (SHA-1, SHA-2)

Usage Notes

Getting Started

Before using this driver, obtain the RZ MPU Security Package (Linux OS) and perform the following steps using the Security Configurator:

  • Inject the Key Update Key (KUK): Required if you use user-generated keys

An Example of Project Configuration for Verifying TSIP Operation

Note
This section applies to RZ/V2L only. For other devices, this configuration is not required.
Warning
The TSIP driver does not operate with the default FSP project configuration. By default, the application is assumed to run in the Non-Secure state: the application code is placed in the Non-Secure address region and the CPU transitions to the Non-Secure state before executing the application. Because the Trusted Secure IP is only accessible from the Secure state, TSIP cannot operate under this default configuration.

The following three changes allow the application to execute while the CPU remains in the Secure state, which is the simplest way to verify TSIP operation. Apply these changes after generating the project and implementing the application, before running it for the first time.

Note
The following steps describe one example configuration for verifying that the TSIP driver operates correctly in a simple standalone project.

Step 1: Disable automatic code generation.

Once you have completed all FSP configuration and the project is ready to build and run (i.e. no further code generation is needed), turn off automatic code re-generation. This prevents the manual changes in Steps 2 and 3 from being overwritten if code generation is accidentally triggered again.

Step 2: Set BSP_NONSECURE_TRANSITION to (0) in bsp_mcu_family_cfg.h.

Open fsp_cfg/bsp/bsp_mcu_family_cfg.h and change the macro definition as follows:

#define BSP_NONSECURE_TRANSITION (0)

This prevents the BSP startup code from transitioning the CPU to the Non-Secure state.

Step 3: Comment out R_BSP_SecurityInit() in SystemInit_S() in systems.c.

Open rz/fsp/src/bsp/cmsis/Device/RENESAS/Source/systems.c and comment out the call to R_BSP_SecurityInit() inside SystemInit_S(). Although the CPU remains in the Secure state after Step 2, the TrustZone boundary configuration performed by R_BSP_SecurityInit() will cause a SecureFault exception when execution jumps to Reset_Handler_NS() in the Non-Secure address region. Commenting out this call disables the TrustZone boundary configuration and prevents this exception:

void SystemInit_S (void)
{
/* R_BSP_SecurityInit(); */ /* Commented out to disable TrustZone boundary configuration */
...
}
Note
The configuration changes described above cause the CPU to remain in the Secure state throughout application execution. If you incorporate modules other than TSIP into the same project, be aware that most FSP middleware and driver modules are designed to operate in the Non-Secure state and may not function correctly under this configuration.

Key Management

Initialization of tsip_wrapped_key_t

All instances of tsip_wrapped_key_t must be properly initialized. Set the key type in tsip_wrapped_key_t::type, and assign the address of the wrapped key value to tsip_wrapped_key_t::p_value.

tsip_wrapped_key_t wuk = {.type = TSIP_KEY_TYPE_AES_256, .p_value = WUK_VAL_ADDR};

Key Update

In key update, the pre-injected Key Update Key (KUK) is used. Prepare two instances of tsip_wrapped_key_t: one for the KUK and one for the newly generated wrapped key. Set the p_value of the KUK to point to the KUK stored in ROM, and set the other p_value to point to a buffer in RAM. When R_TSIP_EncryptedKeyWrap() is called, the wrapped key value is output to the buffer. The value should be stored in ROM just like in key injection.

(1) Key injection phase

Use the Security Configurator in the RZ MPU Security Package (Linux OS) to inject the KUK.

(2) Key Update phase

uint8_t wuk_buf[TSIP_BYTE_SIZE_WRAPPED_KEY(TSIP_KEY_TYPE_AES_256)] = {0};
tsip_wrapped_key_t wuk = {.type = TSIP_KEY_TYPE_AES_256, .p_value = wuk_buf};
tsip_wrapped_key_t kuk = {.type = TSIP_KEY_TYPE_KUK, .p_value = KUK_VAL_ADDR};
R_TSIP_EncryptedKeyWrap(&g_tsip_ctrl, &kuk, iv, euk, &wuk);
/* Write wuk_buf to Non-volatile memory. */

Key Generation

In key generation, set p_value to point to a buffer in RAM. When R_TSIP_KeyGenerate() or R_TSIP_KeyPairGenerate() is called, the wrapped key value will be output to that buffer. If you need to retain the key, store it in ROM. If the key is an ephemeral key generated by the application and does not need to be stored, the wrapped key can be used directly for cryptographic operations.

Symmetric key

uint8_t wuk_buf[TSIP_BYTE_SIZE_WRAPPED_KEY(TSIP_KEY_TYPE_AES_256)] = {0};
tsip_wrapped_key_t wuk = {.type = TSIP_KEY_TYPE_AES_256, .p_value = wuk_buf};
R_TSIP_KeyGenerate(&g_tsip_ctrl, &wuk);
/* Write wuk_buf to Non-volatile memory or use wuk directly. */

Asymmetric key

uint8_t wuk_pub_buf[TSIP_BYTE_SIZE_WRAPPED_KEY(TSIP_KEY_TYPE_ECC_SECP256R1_PUBLIC)] = {0};
uint8_t wuk_priv_buf[TSIP_BYTE_SIZE_WRAPPED_KEY(TSIP_KEY_TYPE_ECC_SECP256R1_PRIVATE)] = {0};
tsip_wrapped_key_t wuk_pub = {.type = TSIP_KEY_TYPE_ECC_SECP256R1_PUBLIC, .p_value = wuk_pub_buf};
tsip_wrapped_key_t wuk_priv = {.type = TSIP_KEY_TYPE_ECC_SECP256R1_PRIVATE, .p_value = wuk_priv_buf};
R_TSIP_KeyPairGenerate(&g_tsip_ctrl, &wuk_pub, &wuk_priv);
/* Write wuk_pub_buf/wuk_priv_buf to Non-volatile memory or use wuk_pub/wuk_priv directly. */

Usage of wrapped key value stored in non-volatile memory

When using a wrapped key value stored in non-volatile memory, set p_value to point to the wrapped key value.

tsip_wrapped_key_t wrapped_key = {.type = TSIP_KEY_TYPE_AES_256, .p_value = ADDR_WUK};

State Transition

This driver has the following states.

State Name Details
STATE_INITIAL Driver is not open.
STATE_MAIN Ready to Compute.
STATE_AES Computing AES (unauthenticated cipher)
STATE_AES_AEAD Computing AES (AEAD).
STATE_AES_MAC Computing AES (MAC).
STATE_SHA Computing SHA.
STATE_HMAC Computing HMAC.
STATE_KDF_SHA Computing SHA for KDF.
STATE_KDF_HMAC Computing HMAC for KDF.

There are two types of APIs provided by the TSIP driver for accelerating cryptographic operations: those that provide cryptographic operations in a single API and those that provide them in multiple APIs. In this document, the former is referred to as single-part operations and the latter as multi-part operations. Each corresponds to the following algorithms:

  • Single-part operations: DRBG, Key management, ECC, RSA, SHA, HMAC
  • Multi-part operations: AES, SHA, SHA for KDF, HMAC, HMAC for KDF

Multi-part operations are APIs which split a single cryptographic operation into a sequence of separate steps (e.g. Init-Update-Finish). This enables fine control over the configuration of the cryptographic operation, and allows the message data to be processed in fragments instead of all at once.

Due to the above characteristics, it is necessary to manage the operational states in the multi-part operations.

Tips

Infinite Loop

If TSIP detects software corruption of this driver, TSIP stops working. In this case, the program will stall in an infinite loop in the TSIP driver. The loop can be exited using any of the following methods.

  1. Use a watchdog timer.
  2. Define TSIP_POLLING_LOOP_LIMIT as an unsigned integer in the compiler options. Then the infinite loops in the driver will be replaced with a software loop with TSIP_POLLING_LOOP_LIMIT as upper bound. The recommended value is TSIP_POLLING_LOOP_LIMIT=100000000 when the CPU-to-TSIP clock ratio is 10:1. The number of loops required varies depending on the clock ratio and the content of the calculation, so adjust as necessary.
Note
If the argument p_key_update_key->p_value of R_TSIP_EncryptedKeyWrap() is an invalid value, it is also treated as software corruption.

Limitations

The TSIP driver of this version has no limitation.

Examples

AES cipher Example

This is an example of AES-CTR encryption/decryption.

void r_tsip_example_aes ()
{
fsp_err_t err;
static const uint8_t plain[TSIP_PRV_BYTE_SIZE_AES_BLOCK * 2] BSP_ALIGN_VARIABLE(4) =
{
0x52, 0x65, 0x6e, 0x65, 0x73, 0x61, 0x73, 0x20, 0x45, 0x6c, 0x65, 0x63, 0x74, 0x72, 0x6f, 0x6e,
0x69, 0x63, 0x73, 0x20, 0x43, 0x6f, 0x72, 0x70, 0x6f, 0x72, 0x61, 0x74, 0x69, 0x6f, 0x6e, 0x00
};
uint8_t iv[TSIP_PRV_BYTE_SIZE_AES_BLOCK] BSP_ALIGN_VARIABLE(4) = {0};
uint8_t cipher_calculated[TSIP_PRV_BYTE_SIZE_AES_BLOCK * 2] BSP_ALIGN_VARIABLE(4) = {0};
uint8_t plain_calculated[TSIP_PRV_BYTE_SIZE_AES_BLOCK * 2] BSP_ALIGN_VARIABLE(4) = {0};
/* Prepare wrapped key data area */
uint8_t wrapped_key_value[TSIP_BYTE_SIZE_WRAPPED_KEY(TSIP_KEY_TYPE_AES_256)] BSP_ALIGN_VARIABLE(4);
tsip_wrapped_key_t wrapped_key =
{
.type = TSIP_KEY_TYPE_AES_256, .p_value = &wrapped_key_value
};
/* Initialize the driver */
err = R_TSIP_Open(&g_tsip_ctrl, &g_tsip_cfg);
assert(FSP_SUCCESS == err);
/* Generate a aes 256-bit key */
err = R_TSIP_KeyGenerate(&g_tsip_ctrl, &wrapped_key);
assert(FSP_SUCCESS == err);
/* Generate a nonce */
err = R_TSIP_RandomNumberGenerate(&g_tsip_ctrl, iv);
assert(FSP_SUCCESS == err);
/* Encrypt a plaintext */
err = R_TSIP_AES_Cipher_Init(&g_tsip_ctrl, TSIP_AES_CIPHER_MODE_CBC_ENC, &wrapped_key, iv);
assert(FSP_SUCCESS == err);
err = R_TSIP_AES_Cipher_Update(&g_tsip_ctrl, plain, cipher_calculated, TSIP_PRV_BYTE_SIZE_AES_BLOCK * 2);
assert(FSP_SUCCESS == err);
err = R_TSIP_AES_Cipher_Finish(&g_tsip_ctrl);
assert(FSP_SUCCESS == err);
/* Decrypt a ciphertext using the same key */
err = R_TSIP_AES_Cipher_Init(&g_tsip_ctrl, TSIP_AES_CIPHER_MODE_CBC_DEC, &wrapped_key, iv);
assert(FSP_SUCCESS == err);
err = R_TSIP_AES_Cipher_Update(&g_tsip_ctrl, cipher_calculated, plain_calculated, TSIP_PRV_BYTE_SIZE_AES_BLOCK);
assert(FSP_SUCCESS == err);
err = R_TSIP_AES_Cipher_Update(&g_tsip_ctrl,
cipher_calculated + TSIP_PRV_BYTE_SIZE_AES_BLOCK,
plain_calculated + TSIP_PRV_BYTE_SIZE_AES_BLOCK,
TSIP_PRV_BYTE_SIZE_AES_BLOCK);
assert(FSP_SUCCESS == err);
err = R_TSIP_AES_Cipher_Finish(&g_tsip_ctrl);
assert(FSP_SUCCESS == err);
/* Compare plain and plain_calculated */
assert(0 == memcmp(plain, plain_calculated, TSIP_PRV_BYTE_SIZE_AES_BLOCK * 2));
/* Close the driver */
err = R_TSIP_Close(&g_tsip_ctrl);
assert(FSP_SUCCESS == err);
}

err = R_TSIP_AES_AEAD_Init(&g_tsip_ctrl, TSIP_AES_AEAD_MODE_GCM_ENC, &wrapped_key, nonce, GCM_NONCE_LEN);
assert(FSP_SUCCESS == err);
/* Input AAD */
err = R_TSIP_AES_AEAD_AADUpdate(&g_tsip_ctrl, aad, GCM_AAD_LEN);
assert(FSP_SUCCESS == err);
/* Input plaintext (one-shot) */
err = R_TSIP_AES_AEAD_Update(&g_tsip_ctrl, plain, GCM_TEXT_LEN, cipher_calculated, &output_length_tmp);
output_length += output_length_tmp;
assert(FSP_SUCCESS == err);
/* Output remaining text and generate a tag */
err = R_TSIP_AES_AEAD_Finish(&g_tsip_ctrl, cipher_calculated + output_length, &output_length_tmp, tag);
assert(FSP_SUCCESS == err);
/* Decrypt a ciphertext using the same key */
err = R_TSIP_AES_AEAD_Init(&g_tsip_ctrl, TSIP_AES_AEAD_MODE_GCM_DEC, &wrapped_key, nonce, GCM_NONCE_LEN);
assert(FSP_SUCCESS == err);
/* Input AAD */
err = R_TSIP_AES_AEAD_AADUpdate(&g_tsip_ctrl, aad, GCM_AAD_LEN);
assert(FSP_SUCCESS == err);
input_length = 0;
output_length = 0;
/* Input ciphertext (multi-shot) */
input_length_tmp = 10;
err = R_TSIP_AES_AEAD_Update(&g_tsip_ctrl,
cipher_calculated + input_length,
input_length_tmp,
plain_calculated + output_length,
&output_length_tmp);
input_length += input_length_tmp;
output_length += output_length_tmp;
assert(FSP_SUCCESS == err);
input_length_tmp = GCM_TEXT_LEN - input_length;
err = R_TSIP_AES_AEAD_Update(&g_tsip_ctrl,
cipher_calculated + input_length,
input_length_tmp,
plain_calculated + output_length,
&output_length_tmp);
output_length += output_length_tmp;
assert(FSP_SUCCESS == err);
/*
* Output remaining text and verify the tag
* Attention: Do not use the output plaintext by R_TSIP_AES_Cipher_DecryptUpdate()
* before R_TSIP_AES_Cipher_DecryptFinal() returns FSP_SUCCESS.
* The integrity is checked in this function.
*/
err = R_TSIP_AES_AEAD_Verify(&g_tsip_ctrl, plain_calculated + output_length, &output_length_tmp, tag, GCM_TAG_LEN);
assert(FSP_SUCCESS == err);
/* Compare plain and plain_calculated */
assert(0 == memcmp(plain, plain_calculated, GCM_TEXT_LEN));
/* Close the driver */
err = R_TSIP_Close(&g_tsip_ctrl);
assert(FSP_SUCCESS == err);
}
